03 / RETRIEVAL EXPLAINED

两类检索，回答不同问题。

文档 RAG 查“稿件写了什么”；审稿人推荐查“谁可能适合评审”。二者共享部分基础设施，但数据和排序逻辑不同。

⌕

用小块匹配，用大块提供上下文。

例如：“这篇稿件如何评估检索效果？”系统在当前成功解析的稿件中找证据，返回命中的子块以及所属父章节。

  1. 父子分块章节 → 细粒度片段
  2. 双路召回BM25 + 向量
  3. RRF 融合按排名合并候选
  4. 可选增强重排 / 反思
  5. 证据返回片段 + 父级上下文

为什么要分层切块？

父块目标约 1,600 个估算 token，子块目标 480，重叠 64。短片段方便定位，父章节保留语境。表格作为原子块保存，即使超出目标长度也会保留并标记。

长度使用 heuristic_cjk_word_v1 估算，不是模型 tokenizer 的精确计数。

为什么同时用词汇和向量？

BM25 擅长术语匹配；Ollama 向量用于语义相似度检索。RRF 以各路排名融合结果，避免直接相加不同量纲的分数。PostgreSQL 支持 pgvector；兼容路径使用 JSON 向量和内存计算。

展开可选增强与故障降级
  • Query Rewrite / HyDE：默认关闭；分别改写问题、生成用于检索的假设性文档。假设文档不能作为事实依据。
  • Cross-Encoder：配置 RERANKER_MODEL 并安装可选依赖后生效；失败回退到融合排序。
  • Self-RAG：可选让模型评估证据支持程度，模型判断仍需复核。
  • CRAG：默认关闭，低质量时尝试调用自行配置的外部搜索适配器；仓库未内置可直接使用的搜索服务。
  • 向量服务故障：保留 BM25，返回 degraded、degraded_reasons 和 route_status。查询增强本身失败仍可能让请求失败。

未经过重排或反思验证的非空结果可标记为 unverified；检索分数不能直接解释为“结论可信概率”。

◎

先确定候选资格，再比较匹配程度。

输入为稿件标题、摘要、关键词与作者机构。候选数据来自本地审稿人画像、历史论文和合作者关系。

  1. 冲突过滤机构 / 近年合作者
  2. 三路召回sparse / dense / metadata
  3. 融合与重排RRF + 可选模型
  4. 业务排序活跃度 / 工作量
  5. 候选名单代表论文 + 评分拆解

三路召回各看什么？

Sparse 在 PostgreSQL 上使用全文检索，回退路径按词汇重叠评分；Dense 比较稿件与候选论文的向量；Metadata 利用专业关键词和近期发表数量。审稿人稀疏路线并非文档 RAG 中的 BM25。

默认如何排序？

未启用 Cross-Encoder 时，重排基线为 0.55 × dense + 0.30 × sparse + 0.15 × metadata，再加入融合与活跃度奖励、工作量惩罚。页面展示分数组成，支持编辑复核。

展开筛选约束与真实局限
  • 同机构匹配使用去空白、转小写后的名称，不能自动识别所有机构别名。
  • 合作者冲突依赖已有关系，按当前年份减 5 的阈值筛选；数据库缺失的关系无法凭空发现。
  • 年份条件表示候选人至少有一篇达到阈值的论文，不保证全部推荐证据都满足该年份。
  • 机构多样性是优先策略：不同机构人数不足时会补入其余候选人，不是强制一机构一人。
  • 有些候选人可能仅来自画像或元数据，没有足够论文证据。向量路线不可用时可能静默回退，不能套用文档 RAG 的完整降级字段。

04 / INSIDE THE AGENT

一句编辑需求，怎样变成行动？

这是一个 LangGraph 单 Agent 工具循环。Skills 按需提供流程指引；工具按结构化参数执行具体任务。

理解 → 调工具 → 看结果 → 继续

DeepSeek 根据编辑需求和已有上下文选择工具。工具返回结构化结果，模型再判断是否继续，直到给出答案或达到预算上限。

Context→Model→Tools工具结果回到上下文，进入下一轮 ↶
6 轮 / 12 次
默认模型轮数与工具调用上限，可配置；预算耗尽后尝试基于已有结果总结。
10 个工具 / 4 个 Skills
默认注册表包含技能加载、证据检索、学术核验、推荐、解释和草稿；技能覆盖投稿检查、稿件分析、候选选择、邀请准备。
模板邀请草稿
工具使用候选姓名、稿件标题和已有论文标题拼装英文邮件，输出标记为待人工复核。

用于解释可能的工具序列；真实模型的选择、返回结果和轮数可能不同。该演示不产生真实推荐。

工具权限

READ 与 DRAFT 可自动执行；ACTION 默认要求审批。代码具备 interrupt / resume 机制，但默认注册表中没有实际 ACTION 工具。

上下文管理

工具结果限长、Snip、Microcompact、Context Collapse、模型摘要逐层控制上下文。摘要失败连续达到阈值后停止自动压缩尝试。

持久化与恢复

AgentRun.id 对应 thread_id，Django 保存检查点。Celery 租约与超时对账控制重复执行；不提供外部动作 exactly-once 保证。

06 / MEASURE WHAT MATTERS

能执行，与做得对，都要验证。

HTTP 202 表示任务被接受；运行 success 也可能来自预算结束。产品效果需要独立标注与任务验收。

R

检索质量

使用 qrels 标注证据相关性，计算 Recall、MRR、nDCG。指标与标注覆盖率一起看；未标注不等于不相关。

A

Agent 质量

评估工具选择、参数、调用顺序及规则通过情况。任务成功、证据支持、约束保留等结果仍需人工判断。

Δ

回归与对比

按稿件或任务组冻结 dev / test，对同一组案例进行版本对照。失败案例保留，追踪根因、修改与回归结果。

仓库提供评测能力，不代表已经证明业务效果。

demo_cases.jsonl 是 synthetic 合成示例。自动测试使用受控模型和工具返回值，不能替代真实模型任务成功率。token 统计也不覆盖全部内部调用成本。

07 / RUN IT YOURSELF

看懂之后，把项目跑起来。

这张网页无需安装即可阅读；运行完整编辑工作台，需要自己的后端服务、数据和模型配置。

本地运行需要什么？

  1. Docker 与 Compose运行 Django、PostgreSQL、Redis、worker、beat 和前端。
  2. DeepSeek API Key用于元数据抽取与 Agent 推理；填入本地 .env。
  3. Ollama 与 embedding 模型默认 nomic-embed-text:latest；容器需要能访问 Ollama 地址。
  4. 审稿人数据与索引新安装不会附带真实稿件或候选库。先导入数据，再按需回填论文和文档向量。
PowerShell / 项目启动
git clone git@github.com:HxZhu0629/rrs_editor_agent.git
cd rrs_editor_agent
Copy-Item .env.example .env

# 先编辑 .env：配置随机密钥、DeepSeek Key 和 Ollama 地址
ollama pull nomic-embed-text:latest
docker compose -f docker-compose.yml up -d --build
服务就绪后访问 http://localhost。显式指定 compose 文件可避开本机专用 override 配置。
导入数据与生成向量

使用仓库脚本抓取或准备符合导入格式的 OpenAlex JSON。以下命令假定文件已准备好；实际文件路径和规模按需调整。

docker compose -f docker-compose.yml cp data/your-dataset.json backend:/tmp/dataset.json
docker compose -f docker-compose.yml exec backend python manage.py import_openalex_dataset --file /tmp/dataset.json
docker compose -f docker-compose.yml exec backend python manage.py backfill_reviewer_paper_embeddings --only-missing
docker compose -f docker-compose.yml exec backend python manage.py backfill_document_chunk_embeddings --only-missing

数据获取和导入代码可能填入演示邮箱或 noemail.local 占位邮箱，这些不是核验过的联系方式。邀请前需要确认真实身份与联系方式。

08 / BEFORE YOU GO

边界，讲清楚才有用。

这是可直接对外提供服务的生产系统吗？

当前适合作为原型与学习项目。API 默认 AllowAny，CORS 全放开，尚未实现用户级数据隔离。公网部署完整系统需要落实身份认证、授权、TLS、媒体访问控制和备份恢复。server compose 只减少公开端口，不会自动补齐这些能力。

可以在这张介绍页上传稿件或和模型对话吗？

本页是独立静态导览，按钮只切换预设讲解内容。完整工作台位于 frontend/，连接 Django API 后才能处理稿件和执行 Agent。真实模型调用可能产生费用，取决于模型供应商和使用量。

会自动发送审稿邀请吗？

不会。当前草稿工具没有邮件发送能力。工程中预留 ACTION 审批与恢复机制，并通过受控测试工具验证；如要接入真实外部动作，仍需增加发送工具、权限与幂等处理。

代码里的“记忆”和“技能”是什么？

记忆是按 managed、user、project、local、auto、team 加载的分层指令，支持文件 include 与路径条件；它不是自动训练出的长期知识库。Skills 是包含工具建议和完成检查的可信流程说明，按需载入同一个 Agent 上下文。

这个导览的内容依据是什么？

介绍依据 backend/apps/ 下的接口、检索、Agent、数据模型和配置实现编写。源码入口链接到 main 分支，具体行为以实际运行版本为准。页面中的流程示意和预设轨迹不作为真实实验或业务指标。
